# Функциональные требования

## 1. Общие положения

Функциональные требования определяют возможности информационной системы документооборота предприятия с модулем автоматизации конфигурации серверной инфраструктуры.

Каждое требование имеет уникальный идентификатор и описывает отдельную функцию системы. Требования формулируются таким образом, чтобы их реализацию можно было проверить в ходе тестирования.

В документе используются следующие обозначения:

- **FR** — Functional Requirement (функциональное требование).
- **Код модуля** — обозначение функциональной подсистемы.
- **Номер** — порядковый номер требования внутри соответствующего модуля.

Требования относятся к предполагаемой первой версии системы. Их состав и детализация могут уточняться по мере проектирования.

## 2. Структура функциональных модулей

| Код | Модуль | Назначение |
|---|---|---|
| AUTH | Аутентификация | Вход пользователей и проверка доступа |
| USER | Управление пользователями | Учётные записи и назначение ролей |
| DOC | Документооборот | Создание, регистрация и сопровождение документов |
| APPROVAL | Согласование | Маршруты согласования и фиксация решений |
| FILE | Хранение файлов | Вложения, версии файлов и электронные акты |
| SERVER | Реестр серверов | Учёт целевых серверов и их параметров |
| EXEC | Исполнение конфигураций | Запуск сценариев Ansible и получение результатов |
| AUDIT | Аудит | История действий пользователей и технических операций |
| ACT | Результаты работ | Формирование итоговых актов |
| UI | Пользовательский интерфейс | Отображение данных и взаимодействие с функциями системы |

| ID | Требование |

| FR-AUTH-002 | Система должна проверять подлинность учётных данных при входе. |
| FR-AUTH-003 | Система должна предоставлять доступ к защищённым функциям только аутентифицированным пользователям. |
| FR-AUTH-004 | Система должна проверять полномочия пользователя перед выполнением защищённых операций. |
| FR-AUTH-005 | Система должна предоставлять пользователю возможность завершить текущий сеанс работы. |
| FR-AUTH-006 | Система должна запрещать выполнение операций, на которые у пользователя отсутствуют необходимые разрешения. |

## 13. Требования, подлежащие уточнению

До окончательного утверждения функциональных требований необходимо определить:

1. Полный перечень статусов документов и допустимые переходы между ними.
2. Правила формирования регистрационных номеров.
3. Порядок изменения документа после направления на согласование и после утверждения.
4. Структуру маршрутов согласования и возможность последовательного или параллельного согласования.
5. Ограничения на размер и тип загружаемых файлов.
6. Перечень параметров, допустимых для каждого сценария Ansible.
7. Поведение системы при частичном успехе или ошибке на одном из нескольких целевых серверов.
8. Состав полей электронного акта и правила его формирования.
9. Точный перечень разрешений каждой роли.
10. Требования к хранению технических журналов и истории действий пользователей.

Уточнение этих пунктов необходимо для детализации требований, проектирования модели данных, разработки диаграмм процессов и подготовки тестовых сценариев.
